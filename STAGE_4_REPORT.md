# Отчёт по этапу 4 — сделки, калькулятор доставки, документы, рекламации

Дата: 2026-11-24 · Версия API: **0.7.0** · Прод: agropost-api.onrender.com + agropost-web.onrender.com

## Что сделано

Четыре блока этапа 4: **(A)** модели данных Deal / Shipment / Document / Claim /
Carrier (+ реквизиты профиля), **(B)** API сделок с действиями статусного
графа, калькулятором доставки и генерацией PDF, **(C)** документы
(pdfmake, шрифты Roboto с кириллицей, white-label), **(D)** UI: экран
«Сделки», карточка с таймлайном, форма с калькулятором, экран реквизитов.
Экономика (налог, маржа) считается **только на сервере**. AI-слой (3.0),
бот/инбокс (3.2) и парсер (2.5) не менялись — только потреблялись.

Выбор по двум вопросам ТЗ: **pdfmake** (не съедает память free-tier,
декларативные шаблоны) и **налог: по умолчанию из профиля, с
переопределением в каждой сделке** (ИП 6% / самозанятый 4% / самозанятый 6%).

## Часть A — модели данных (Prisma, миграция на Neon)

Миграция `20261124131643_stage4_deals_shipments_documents_claims`
(чисто аддитивная: 6 enum, 5 таблиц, 7 ALTER; применена на Neon, задеплоена
через `prisma migrate deploy` — на Render идемпотентно).

```
Carrier   — справочник ТК: name, city, pickupAvailable, isLocal
           (в радиусе 50 км от Павловской — приоритет в калькуляторе)
Deal      — number «СД-0001», leadId?, positionId?, покупатель
           (buyerName/Phone/Region/Inn), volumeKg, salePrice, supplierPrice
           (фиксируется из позиции на момент сделки), taxMode, taxAmount,
           margin, deliveryMethod (PICKUP/TK/FELLOW_TRAVELER), deliveryCost
           (платит покупатель), status (DRAFT→AWAITING_PAYMENT→PAID→
           SHIPPED→DELIVERED→CLOSED, CANCELLED), paidAt/shippedAt/deliveredAt
Shipment  — по сделке: ТК, method, fromCity→toCity, cost, days,
           trackingNumber, status (PENDING/PICKED_UP/IN_TRANSIT/DELIVERED)
Document  — type (INVOICE/CONTRACT/TRANSPORT_NOTE/UPD), number «СЧ-001»,
           fileUrl (base64 PDF, MVP), generatedAt
Claim     — description, photos[] (когда R2), status
           (NEW/IN_REVIEW/RESOLVED/REJECTED/FORWARDED_TO_SUPPLIER),
           resolution, forwardedToSupplier
User      — + ogrnip, address, bank, bik, account (реквизиты для документов)
```

Бизнес-правила зашиты в схему и сервис: доставку всегда оплачивает
покупатель (в маржу не входит — в DTO `deliveryPaidBy: "BUYER"`),
отправка — только после полной оплаты, удалять можно только черновики
и отменённые сделки.

Справочник ТК сеется автоматически (если пуст): ПЭК и СДЭК (Павловская,
isLocal), АгроТранс Кубань, КубаньАвтоЛогистика (локальные, демо),
Деловые Линии и ГрузовичкоФ (Краснодар).

## Часть B — API

- `GET /api/deals?status=ACTIVE|FINISHED|<статус>&q=&period=week|month`
- `POST /api/deals` — из лида (покупатель и позиция подставляются), из
  позиции или вручную; экономика считается на сервере; → DRAFT
- `GET|PATCH|DELETE /api/deals/:id` — PATCH пересчитывает налог/маржу;
  статус — только по графу переходов (shared/deals.ts)
- `POST /api/deals/:id/awaiting-payment|pay|deliver|close|cancel`
- `POST /api/deals/:id/ship` — создаёт Shipment (ТК, города, стоимость,
  трек), статус → SHIPPED
- `GET /api/deals/:id/documents` — список (без base64)
- `POST /api/deals/:id/documents/:type` — генерация PDF (invoice |
  contract | transport_note | upd), возвращает document с fileUrl
- `GET /api/documents/:id/file` — бинарный PDF (attachment)
- `POST /api/deals/calculate-delivery` — {positionId?, toCity, volumeKg}
  → options[] + recommendedIndex: приоритет isLocal, потом по цене;
  если AI-слой доступен — подключается `planLogistics` (заметки и
  рекомендация; цены остаются детерминированными), иначе — формула
- `GET|POST /api/carriers`, `GET|POST /api/claims`, `PATCH /api/claims/:id`
  (forwardedToSupplier → статус FORWARDED_TO_SUPPLIER)
- `GET|PATCH /api/user/profile` — реквизиты + налоговый режим по умолчанию
  (смена режима обновляет taxMode/taxRate пользователя)

## Часть C — генерация документов (pdfmake)

```
apps/server/src/documents/
├── pdfmake.ts        — init (Roboto с кириллицей из пакета, локальные
│                       чтения разрешены, внешние URL запрещены)
├── packages.d.ts     — типы для pdfmake и pdf-parse
├── numbering.ts      — «СЧ-001 → СЧ-002» по счётчику из БД (retry на коллизию)
├── generator.ts      — сборка PDF по типу
├── types.ts          — DocumentData + проверка реквизитов
└── templates/        — invoice.ts (счёт), contract.ts (договор),
    transport.ts (ТН), upd.ts (УПД), common.ts (реквизиты, таблица, подписи)
```

- Реквизиты продавца — из профиля. Не заполнены — честный
  `400 REQUISITES_MISSING` («Заполните реквизиты в профиле»). Для счёта и
  УПД обязательны банковские (р/с, банк, БИК).
- White-label: в документах пользователь — продавец, поставщик не
  упоминается. НДС — «не облагается» с указанием режима (УСН 6% / НПД 4%/6%).
- PDF хранятся **base64 в БД (MVP)**. **R2 — следующий шаг**: перенос
  файлового хранилища в R2, ссылка fileUrl → публичный URL, плюс печать
  (картинка) и фото в рекламациях — отложены до R2.

## Часть D — UI (apps/web)

- **Экран «Сделки»**: карточки (номер, покупатель, культура, объём,
  статус-чип, выручка, маржа зелёным/красным), фильтры
  Все/В работе/Завершены/Отменены, поиск, FAB «Новая сделка».
- **Карточка сделки** (Sheet): таймлайн 6 шагов с текущим этапом и
  кнопками переходов; экономика (маржа крупно, доставка отдельно);
  отгрузка (ТК, маршрут, трек); документы (список + «Скачать» +
  генерация Счёт/Договор/ТН/УПД с автоскачиванием); рекламации
  (создание, переадресация поставщику, «решено»/«отклонить»).
- **Форма создания** (2 шага): позиция (цены подставляются), покупатель,
  объём, цены, налоговый режим (по умолчанию из профиля) + превью маржи
  на лету; шаг 2 — доставка: самовывоз / ТК (калькулятор с вариантами,
  «рекомендуем» и «рядом со складом») / попутчик.
- **Реквизиты** (в «Ещё», /profile): ФИО, ИНН, ОГРНИП, адрес, банк, БИК,
  р/с, налог по умолчанию; предупреждение, если документы не сгенерируются.
- **Пульт**: счётчик «Сделки: N» в шапке; «Ещё»: «Реквизиты и налог»;
  в карточке лида и позиции — кнопка **«Создать сделку»** (предзаполнение
  через stores/deal-create).

## Часть E — маржа и налог (только на сервере)

`shared/pricing.ts` — единый расчёт для сервера, веба и превью:

```
revenue   = salePrice × volumeKg
taxAmount = revenue × ставка режима (ИП 6% / НПД 4% / НПД 6%)
margin    = (salePrice − supplierPrice) × volumeKg − taxAmount
deliveryCost НЕ вычитается — её платит покупатель.
```

## Часть F — тесты (bun test, 98 pass / 0 fail)

- **Unit**: маржа для 3 налоговых режимов (6/4/6%, копейки, демпинг);
  deriveDealTaxMode; нумерация СЧ-001→СЧ-002, Д/ТН/УПД, СД-0001→СД-0002.
- **Golden set документов**: счёт, договор, ТН, УПД — реальный PDF
  (pdfmake) + извлечение текста (pdf-parse v2): номер, дата, продавец,
  покупатель, товар, сумма, «НДС не облагается», самовывоз/доставка;
  white-label (поставщик не упоминается).
- **Валидация реквизитов**: без ФИО/ИНН/адреса и без банка для счёта →
  `REQUISITES_MISSING` (роут отдаёт 400).
- **Интеграционные** (сервис + память, как в 3.2): полный жизненный цикл
  заявка→оплата→отгрузка→доставка→закрытие; запрет обратных переходов;
  отмена/удаление правилами; пересчёт маржи при PATCH; рекламация +
  переадресация; калькулятор: локальные ТК приоритетнее, AI-план
  (пометки + рекомендация, цены детерминированы); нумерация из БД.

## AI на проде — нужен ключ (важно)

Встроенного AI на Render **нет**: код этапа 3.0 ходит прямым HTTP на
`https://api.z.ai/api/paas/v4/chat/completions` с `GLM_API_KEY`; шлюз
песочницы (превью) на прод не переносится. Сейчас прод работает на
fallback-шаблонах — это честно отражено в meta каждого ответа AI.

**Как включить AI на проде:**
1. Получить API-ключ на платформе Z.AI (api.z.ai — консоль → API Keys;
   `GLM_BASE_URL` уже вшит в код).
2. Render Dashboard → сервис **agropost-api** → Environment → добавить
   переменную `GLM_API_KEY` → Save Changes (Render сам пересоберёт сервис).
3. Проверка: `POST https://agropost-api.onrender.com/api/ai/advice` —
   в `meta.provider` должно быть `glm` вместо `fallback`.

Модели: `glm-5.3-flash` (пять кейсов) и `glm-5.3` (pro). Резерв —
OpenRouter: `AI_PROVIDER=openrouter` + `OPENROUTER_API_KEY`. Лимиты
зависят от тарифа аккаунта Z.AI.
