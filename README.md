# АгроПост

## Что это

АгроПост — PWA «тихий помощник» для одного владельца-посредника по торговле
семенами трав и грецким орехом: без ролей, без команды, без напоминаний.
Главное действие — «Разместить»: приложение подбирает каналы по гео-ротации,
генерирует текст объявления с AI (white-label — поставщик не упоминается),
постит в ваши Telegram-каналы через бота и собирает вопросы покупателей
в инбокс с готовым черновиком ответа.

Дальше — сделка целиком в одном окне: экономика с маржой после налога,
калькулятор доставки, счёт/договор/ТН/УПД в PDF, рекламации с фото,
аналитика по каналам и позициям, экспорт в CSV. Работает в мобильном
браузере (375px) и устанавливается как приложение (PWA, офлайн-оболочка).

В этапе 3.0 (AI-слой) реализовано:

- **Слой `apps/server/src/ai/`** — единая точка вызова `gateway.ts`:
  кэш (SHA-256 входа, TTL 24 ч, инвалидация по positionId) → провайдер →
  JSON → zod → **white-label проверка** → при провале retry с усиленным
  промптом → при повторном провале честный **fallback-шаблон**. Приложение
  НИКОГДА не падает из-за AI. Сбой GLM уходит в резервный OpenRouter.
- **Провайдеры**: `providers/glm.ts` — прямой HTTP к Z.AI (провайдеро-
  независимый интерфейс `AiProvider`), `providers/openrouter.ts` — резерв.
  Модели: `glm-5.3-flash` (listing/reply/price/logistics), `glm-5.3`
  (advice). Все ключи — только в `.env` на бэкенде.
- **5 use cases** `POST /api/ai/{listing|reply|advice|price_analysis|logistics}`:
  строгие zod-контракты (title ≤ 70, body ≤ 3000, actions ≤ 3,
  marketPosition из enum, options 2–4 по цене); математика цены
  пересчитывается на сервере (модель не решает арифметику).
- **Журнал `AiCall`**: useCase, inputHash, результат, статус ok/retry/
  fallback/error, токены, модель — аудит и стоимость. White-label:
  имя поставщика/склад/телефон запрещены и в промпте, и проверкой на выходе.
- **Golden set**: 15 кейсов (`src/ai/golden-set.json`) — регрессия при смене
  промптов/моделей; интеграционный тест против реального GLM: `npm run
  test:golden` (пропускается без GLM_API_KEY).
- **Экраны (apps/web)**: «Сгенерировать с AI» в шаге «Текст» мастера
  (skeleton 2–3 с, редактируемое поле, автосохранение в черновик, мягкий
  тост при недоступности AI); «Проверить цену» в карточке позиции (Sheet
  с marketPosition/рекомендацией); «Что сделать?» на Пульте (1–3 карточки
  действий с deep links, «Сейчас всё под контролем» когда пусто).

## Локальный запуск

### База (Neon)

1. Заведите проект на [neon.tech](https://neon.tech), скопируйте connection string.
2. `cd apps/server && cp .env.example .env`, вставьте `DATABASE_URL`.

### Сервер (apps/server)

```bash
cd apps/server
npm install
npm run db:dev        # prisma migrate dev — создать/применить миграции
npm run db:seed       # демо-данные (3 поставщика, 5 культур, 7 позиций)
bun run hash-password # хеш пароля владельца → OWNER_PASSWORD_HASH в .env
npm run dev           # http://localhost:3001/api/health
```

**Авторизация (этап 5.1)**: все приватные маршруты закрыты сессией
владельца. Вход — одна пара из env: `OWNER_LOGIN` + `OWNER_PASSWORD_HASH`
(Argon2id-хеш, пароль открытым текстом не хранится нигде). Без хеша
вход запрещён (fail-closed), а приватное API отвечает 401. Веб сам
перенаправит на `/login` при истёкшей сессии.

### Фронтенд (apps/web)

```bash
cd apps/web
npm install
npm run dev           # http://localhost:5173 — /api проксируется на :3001
```

Сборка и предпросмотр продакшен-версии:

```bash
npm run build
npm run preview
```

По умолчанию сборка ходит на относительный `/api` — так же устроен прод:
статик-сайт проксирует `/api/*` на API-сервис (rewrite в настройках
Render-сайта и в `render.yaml`). Same-origin cookie сессии — вход работает
во всех браузерах (Safari/iOS, блокировка сторонних cookie).
`VITE_API_URL=…` — резерв для ручной cross-origin сборки; тогда cookie
станет сторонней и может отбрасываться браузером.

## Как добавить канал

**Ещё → Каналы → «+».** Поля:

- **Название** — например, «Семена Кубани».
- **Тип** — TG-чат, TG-канал, Авито, Агросервер, MAX, Юла, другая площадка.
- **Ссылка** — `t.me/username`, `t.me/c/XXX` или URL подачи объявления.
- **Регион** — например: ЮФО, Краснодарский край, Федеральный.
- **Город** (необязательно) — для гео-ротации внутри региона; пусто — канал
  на весь регион. Каналы одного региона с городами ≥2 образуют ротацию.
- **Теги** (минимум один) — семена / орех / животноводство / опт / общий.
- **Способ подачи** (этап 2.5) — бот-приёмщик / админ-контакт / форма сайта /
  личный кабинет / не указан. Для бота — его @username
  (@Taganrog_Predlozhka_bot), для админа — контакт (@admn_013).
- **Лимит подач** (необязательно) — например, «2 раза в день».
- **Статус проверки** — «проверен» или «требует проверки» (жёлтый бейдж
  в каталоге — исследование каналов честное).
- **Аудитория** — агро/опт (B2B), локальная барахолка, общая.
- **Подписчики и средний охват** — необязательно, заполняются вручную
  (охват приоритетнее при подборе).
- **Заметки** — условия подачи, контакты администратора (видны только вам).

В карточке канала доступны: «Открыть» (deep link в новой вкладке),
«Скопировать URL», «Изменить», «Удалить» (канал с размещениями удалить
нельзя — сначала удаления).

**Умный подбор при размещении** (этап 2 + 2.1): тег вида товара → свой регион
(ЮФО/Краснодарский край) → «здесь не размещали / размещали давно» →
активность → охват. Алгоритм — `shared/rotation.ts` (`rankForRotation`),
един для API и превью.

### Как работает гео-ротация (этап 2.1)

Ежедневный постинг в одни и те же каналы — спам-сигнал и путь к бану,
поэтому размещаемся по городам региона: Пн — Ростов, Вт — Таганрог,
Ср — Шахты. Каждый канал видит объявление раз в 1–2 недели, покрытие
региона — полное.

- **Cooldown — 3 дня, хардкод** (`COOLDOWN_DAYS` в `shared/rotation.ts`):
  каналу, где размещали меньше трёх дней назад, подборка даёт бейдж
  «⏳ N дн» и ставит его в конец списка (выбрать можно, но с предупреждением).
- Считается по последней публикации в канале — любого объявления
  (банят канал за частоту постинга автора, а не за конкретный товар).
- «Никогда не размещали» — лучшая площадка: свежая аудитория, первый в списке.
- Виджет «Ротация по региону» в мастере появляется, когда у подходящих
  каналов одного региона есть ≥2 городов: показывает, когда в каждом городе
  размещали последний раз, и рекомендует город на сегодня.
- В ротацию входят каналы с тегом товара ИЛИ «общий» (барахолка
  «куплю-продам» принимает любой товар); в саму подборку каналов — только
  строгие совпадения тега (как в этапе 2).
- В ленте Пульта у сводки «размещено в N каналов» появляется подпись
  «Города: …» — если у каналов заполнен город.

Ссылки/телефоны демо-каналов — заглушки: замените на реальные URL чатов
через «Изменить» в карточке канала. В сид 2.5 вошли реальные каналы
исследования ([docs/CHANNEL_RESEARCH.md](./docs/CHANNEL_RESEARCH.md));

### Как работает парсер цен (этап 2.5)

Парсер показывает рынок конкурентов — строка «Рынок: 180–240 ₽/кг
(средняя 205)» в карточке позиции. Данные — только обезличенные
(цены, названия, ссылки — 152-ФЗ, никаких телефонов и ФИО).

- **Агросервер**: robots.txt запрещает `/search/` — поиском не пользуемся.
  Вместо этого читаем официальный `sitemap.xml` (объявления лежат в первых
  чанках), отбираем страницы `/b/*.htm` по транслит-ключевым словам
  («люцерна» → lyutserna, «суданка» → sudan) и вытаскиваем цену из текста
  («180 ₽/кг») — смена вёрстки парсер не ломает. Лимит 1 запрос / 2 сек,
  User-Agent как у браузера. Сайт закрыл контент капчей → статус `blocked`,
  сервис не падает (запустите сбор с другой машины).
- **Telegram**: Telethon (MTProto) с **отдельным** аккаунтом — креды
  `TG_API_ID`/`TG_API_HASH`/`TG_SESSION` в `services/parser/.env`
  (получение сессии: `python -m app.login`). Публичные каналы из
  `TG_CHANNELS`, лимит 1–2 запроса/сек, FloodWait — пауза. Без кредов —
  честный `skipped`, Агросервер продолжает работать.
- **Cron** — раз в 12 часов (`SCHEDULER_INTERVAL_HOURS`); ручной запуск —
  `POST /api/parser/run` (прокси Node-бэкенда, адрес в `PARSER_URL`).
- История цен копится в `CompetitorPrice`; агрегаты по культуре позиции —
  `GET /api/positions/:id/market` (окно 30 дней, кэш раз в день).

Запуск и переменные — [services/parser/README.md](./services/parser/README.md).

## Деплой (только бесплатные tier'ы)

1. **GitHub**: создайте новый репозиторий `agropost` (существующие проекты
   не трогаем) и запушьте этот каталог:
   ```bash
   git init && git add . && git commit -m "Этап 1: поставщики и позиции"
   git remote add origin git@github.com:ВАШ_ЛОГИН/agropost.git
   git push -u origin main
   ```
2. **Neon**: проект `agropost` → connection string в env `agropost-api`.
   Один раз примените миграции и сид локально:
   `DATABASE_URL="..." npm run db:migrate && DATABASE_URL="..." npm run db:seed`
   (Render при деплое тоже выполняет `prisma migrate deploy`).
3. **Render** → New → Blueprint → выберите репозиторий `agropost`.
   Render прочитает `render.yaml` и создаст два сервиса:
   - `agropost-web` (Static Site — не спит; `/api/*` проксируется на API
     через rewrite-правило — same-origin, без `VITE_API_URL`);
   - `agropost-api` (Web Service, free tier — спит через 15 минут бездействия,
     первый запрос после сна ~30 сек; для MVP терпимо).
   В переменные `agropost-api` вставьте `DATABASE_URL` из Neon.
4. **Cloudflare R2** (медиа и сертификаты): отдельный бесплатный аккаунт,
   бакет `agropost-media`, ключи — в env `agropost-api` (см. раздел ниже).
5. **OpenRouter** (этап 3, ИИ): ключ пользователя, только на бэкенде.

Проверка после деплоя: `https://agropost-api.onrender.com/api/health` →
`{"ok":true,...}`; `https://agropost-web.onrender.com` → Пульт с позициями из БД.

## Как настроить R2 (пошагово)

Этап 6: все файлы (PDF документов, фото рекламаций, медиа позиций) идут
через **единое хранилище** `apps/server/src/storage/`:
без R2 — base64 прямо в базе (приложение работает, в логе предупреждение);
с R2 — объекты в бакете, в базе только URL. Переключается env-переменными,
код менять не нужно.

1. **Cloudflare**: заведите аккаунт (бесплатно) → dashboard → **R2 Object
   Storage** → «Create bucket» → имя `agropost-media`.
2. **Публичный доступ**: в бакете Settings → **Public Access** →
   «Connect domain» → выберите `agropost-media.r2.dev` (получите
   `https://pub-xxxx.r2.dev` — это будет `R2_PUBLIC_URL`).
3. **API-ключи**: Cloudflare → R2 → «Manage API tokens» → Create API token
   → Object Storage: **Read & Write**, ограничьте бакетом `agropost-media`
   → скопируйте **Access Key ID** и **Secret Access Key** (секрет показывают
   один раз).
4. **Endpoint**: на странице R2 (Manage API tokens) указан S3 API вида
   `https://<ACCOUNT_ID>.r2.cloudflarestorage.com` — это `R2_ENDPOINT`.
5. **Переменные в Render → agropost-api → Environment** (5 шт):

   | Переменная | Пример |
   |---|---|
   | `R2_ENDPOINT` | `https://abc123….r2.cloudflarestorage.com` |
   | `R2_BUCKET` | `agropost-media` |
   | `R2_ACCESS_KEY_ID` | из шага 3 |
   | `R2_SECRET_ACCESS_KEY` | из шага 3 |
   | `R2_PUBLIC_URL` | `https://pub-xxxx.r2.dev` |

   Сохранить → сервис перезапустится → `GET /api/meta` покажет
   `"storage":{"mode":"r2"}`. `R2_CONFIGURED` задавать не обязательно:
   R2 включается автоматически, когда все 5 значений на месте
   (`R2_CONFIGURED=false` — принудительно выключить).

6. **CORS** — нужен только для presigned-загрузки из браузера напрямую
   (мастер позиций при настроенном R2). В настройках бакета (Settings →
   CORS policy) вставьте:

```json
[
  {
    "AllowedOrigins": ["https://agropost-web.onrender.com", "http://localhost:5173"],
    "AllowedMethods": ["PUT"],
    "AllowedHeaders": ["content-type"],
    "MaxAgeSeconds": 3600
  }
]
```

Без настроенного R2 приложение полностью работает: PDF и фото хранятся
в базе (base64), в логе при старте честное предупреждение, видео для позиций
загрузить нельзя (нужен R2) — кнопка честно об этом говорит.

## Как подключить YML-фид (этап 9 — автообновление площадок)

**Зерно Он-Лайн (zol.ru) и Своё Фермерство (svoefermerstvo.ru)** обновляют
объявления сами: вы один раз вставляете в личный кабинет площадки ссылку
на XML-фид — и дальше АгроПост отдаёт им все позиции «в наличии»
(цены с наценкой, атрибуты, фото, white-label текст). Убрали позицию из
наличия — она уходит из фида, площадка снимет объявление.

1. **Сгенерируйте токен фида** (случайные 32 символа):

   ```bash
   openssl rand -hex 16
   # например: 4f1c9a2e8b7d63f05c2a1e9d8f4b7c30
   ```

2. **Render → agropost-api → Environment**, добавьте:

   | Переменная | Пример |
   |---|---|
   | `FEED_TOKEN` | `4f1c9a2e8b7d63f05c2a1e9d8f4b7c30` |
   | `FEED_SHOP_URL` | `https://agropost-web.onrender.com` (по умолчанию) |

   Сохранить → Manual Deploy («Clear build cache & deploy»). Без токена
   фиды отключены: `/api/feeds/*` отвечает 403 и не раскрывает структуру.

3. **Скопируйте адрес фида**: в приложении «Ещё» → «Настройки» →
   «Фиды площадкам» — кнопка копирования. Ссылка вида:

   ```
   https://agropost-api.onrender.com/api/feeds/yml?token=4f1c9a2e…
   ```

4. **Зерно Он-Лайн** (doska.zol.ru): личный кабинет → подача объявления
   → автозагрузка/импорт по XML (или напишите администратору доски
   «подключите импорт по YML-ссылке») → вставьте скопированную ссылку.
5. **Своё Фермерство** (svoefermerstvo.ru): кабинет продавца
   → интеграции/импорт каталога → вставьте ту же ссылку.

Площадки опрашивают фид сами (наш кэш — 1 час); при расхождении их
форматов можно отдать ту же ссылку в поддержке площадки — это стандартный
YML Яндекс.Маркета. Кэш сбрасывается при каждом деплое. Проверить фид
вручную: открыть ссылку из шага 3 в браузере — увидите XML со всеми
позициями «в наличии».

## Как подключить Авито API (этап 9 — Автозагрузка)

Официальный и бесплатный API (никакой эмуляции): вы передаёте Авито адрес
XML-фида Автозагрузки (Ads v3), площадка сама создаёт/обновляет объявления
и снимает отсутствующие. Перед отправкой — dry-run с превью XML и
подтверждением.

1. **Получите ключи**: Авито → «Для бизнеса» → «Интеграции» → API
   (нужен профиль ИП/юрлица, регистрация бесплатная) → скопируйте
   **client_id** и **client_secret**. Там же посмотрите **ID профиля**.
2. **Render → agropost-api → Environment**:

   | Переменная | Пример |
   |---|---|
   | `AVITO_CLIENT_ID` | из кабинета Авито |
   | `AVITO_CLIENT_SECRET` | из кабинета Авито |
   | `AVITO_USER_ID` | `123456789` (id профиля) |
   | `AVITO_CONTACT_PHONE` | `+7 900 000-00-00` (телефон в объявлениях) |

   (можно и без env — ввести ключи в «Ещё» → «Настройки» → «Авито API»;
   env имеет приоритет). Без ключей приложение работает как раньше —
   полуавто, с честным предупреждением «Авито API не настроен».

3. **Проверьте подключение**: «Ещё» → «Настройки» → «Авито API» →
   «Проверить подключение» — реально получает OAuth-токен.
4. **Публикация**: мастер «Разместить» → шаг 3, канал «Авито» → кнопка
   **«Опубликовать на Авито»** → превью XML (dry-run: локальная валидация
   лимитов Авито + удалённая, если доступна) → **«Подтвердить отправку»** →
   Авито забирает фид, объявления обновляются за несколько минут.
5. **Категории** при желании подстройте через `AVITO_CATEGORY_SEED` /
   `AVITO_CATEGORY_NUT` (по умолчанию «Товары для дома и дачи» /
   «Продукты питания») — первый dry-run в валидаторе Авито покажет
   расхождения, если каталог категорий у вашего города другой.

Что автоматизировано, а что вручную — бейджи в мастере «Разместить»:
🟢 **Авто** — YML-площадки, Авито API, свой бот-админ, MAX-бот-админ;
🟡 **Полуавто** — чужие чаты, Агросервер (текст готовит приложение);
🔴 **Ручной** — НССиС (только точка входа). Список каналов в сиде этапа 9
дополнен: Зерно Он-Лайн, Своё Фермерство, Авито, Агросервер, НССиС
(20 реальных TG/MAX-каналов + 5 площадок; свои каналы не трогаются).

## Как подключить MAX-бота (этап 10)

MAX (мессенджер max.ru) имеет официальный Bot API — документация
dev.max.ru (базовый домен `platform-api2.max.ru`, авторизация заголовком
`Authorization: <access_token>`). Всё бесплатно.

1. **Создайте бота**: max.ru → раздел для разработчиков dev.max.ru →
   «Чат-боты» → создать бота → скопируйте `access_token`.
2. **Задайте env на Render** (или введите токен в «Ещё» → «Настройки» →
   «MAX» — env имеет приоритет):
   - `MAX_BOT_TOKEN` — токен бота;
   - `MAX_USER_ID` — ваш ID в MAX (необязательно: придёт апдейтом
     `bot_started`, когда напишете боту; нужен, чтобы бот не считал
     ваши сообщения лидами).
3. **Проверьте**: «Настройки → MAX» → «Проверить подключение» — реально
   вызывает `GET /me` и показывает имя бота.
4. **Вопросы покупателей** работают сразу: бот слушает личные чаты
   (long polling `GET /updates`, marker-based), создаёт лиды `source=MAX`
   в инбоксе (фильтр-бейдж «MAX»), отвечает покупателю от имени бота.
   Уведомления вам — в Telegram-бот (тот же дайджест).
5. **Публикация в свои каналы**: добавьте бота **админом** канала MAX
   (право `write`; первого админа-бота назначает человек в интерфейсе).
   ID чата API отдаёт только апдейтом — когда бота добавят, `chat_id`
   появится в «Настройки → MAX» автоматически (событие `bot_added`).
   Дальше в мастере «Разместить» у MAX-каналов кнопка
   «Опубликовать в MAX»: проверка прав бота → анти-бан 24 ч → пост
   с диплинком `https://max.ru/<bot>?start=lst_…` (аттрибуция лида).

Без токена приложение работает как раньше (полуавто): MAX-каналы в
каталоге с бейджем «Авто» по умолчанию, публикация — копированием текста.

## Как настроить userbot — чтение чужих TG-чатов (этап 10)

Userbot — отдельный Python-сервис (services/userbot, Telethon/MTProto),
который **только читает** новые сообщения в выбранных чатах и создаёт
лиды `TELEGRAM_CHAT` в инбоксе. Ничего не отправляет (анти-бан: в коде
нет ни одного пишущего вызова MTProto — проверяется тестом).

1. **Отдельный Telegram-аккаунт** (не основной и не парсерный!):
   зарегистрируйте новый номер, один раз локально выполните
   `cd services/userbot && python -m app.login` — скрипт попросит телефон
   и код и напечатает строку `StringSession`.
2. **Запустите сервис** (Render web service или локально):
   ```
   cd services/userbot && pip install -r requirements.txt
   python -m uvicorn app.main:app --port 8010   # .env рядом
   ```
3. **env сервиса** (см. services/userbot/README.md):
   - `DATABASE_URL` — та же база Neon, что у основного API;
   - `TELEGRAM_API_ID` / `TELEGRAM_API_HASH` — общие с парсером креды;
   - `TELEGRAM_SESSION` — строка StringSession отдельного аккаунта;
   - `CHATS_TO_READ` — чаты через запятую (@username или ID);
   - `TELEGRAM_BOT_TOKEN` / `TELEGRAM_USER_ID` — уведомления вам
     («Новое сообщение в чате "X": …») идут **ботом**, не userbot.
4. **Чаты можно добавлять из UI**: «Ещё» → «Настройки» → «Userbot
   (чтение)» → «Добавить чат» (@username или ссылка t.me/…). Сервис
   перечитывает список раз в минуту — рестарт не нужен.
5. **Фильтр ключевых слов** (люцерна, эспарцет, суданка, орех, семена,
   куплю, продам, цена) — болтовня в лиды не попадает. Меняется env
   `USERBOT_KEYWORDS`.
6. **Ответ покупателю** — из инбокса приложения (вручную) или через
   Telegram-бота: userbot ничего не пишет.

Живой статус — `GET :8010/health`; в приложении — «Настройки → Userbot»
(подключён, чатов, лидов сегодня, последнее сообщение). Без env-кредов
сервис честно отвечает «не настроено» — приложение работает как раньше.

## Управление секретами (переменные окружения в UI)

«Ещё» → «Настройки»: фиды, Telegram-бот, AI (OpenRouter), Авито API и MAX
можно настроить прямо в приложении — без захода в панель Render.

**Что управляется**: FEED_TOKEN (фиды), AVITO_CLIENT_ID / AVITO_CLIENT_SECRET /
AVITO_USER_ID / AVITO_CONTACT_PHONE (Авито API), MAX_BOT_TOKEN (MAX),
OPENROUTER_API_KEY (AI), TELEGRAM_BOT_TOKEN / TELEGRAM_USER_ID (бот).

**Как это устроено**:

- **env имеет приоритет**: переменная, заданная на Render, показывает
  «через env» — поле только для чтения, правка в UI заблокирована (400).
- **Шифрование**: значения из UI хранятся в AppSetting (PostgreSQL)
  ТОЛЬКО в виде шифротекста AES-256-GCM. Ключ — env `SECRETS_ENCRYPTION_KEY`
  (сгенерируйте: `openssl rand -hex 32`). В базе нет открытых секретов,
  при дампе БД утекают только шифротексты.
- **Клиент видит маски**: `••••1234` и флаг «настроено/не настроено» —
  сырые значения из API не отдаются.
- **«Проверить подключение»** — реальный запрос к сервису: Авито OAuth
  (`POST /token`), MAX (`GET /me`), OpenRouter (`GET /api/v1/auth/key`),
  Telegram (`getMe`); фиды — запрос к собственному фиду по токену.
- **Когда вступает в силу**: фиды и Авито — сразу; MAX-публикация — сразу
  (приём сообщений — после перезапуска); OpenRouter и Telegram-бот —
  после перезапуска API (подсказка на экране).
- **Аудит**: каждое изменение — запись в таблицу AuditLog (кто, когда,
  какое поле, маски было → стало). Последние изменения — на экране
  «Настройки» → «История переменных».

**Без SECRETS_ENCRYPTION_KEY** экран показывает честный баннер
«Управление секретами недоступно», сохранение через UI отключено (503),
а env-переменные продолжают работать — приложение не падает.

**Смена ключа шифрования**: сохранённые значения расшифровать нельзя —
задайте их заново в UI (старые записи будут перезаписаны при сохранении).

## Быстрый старт для пользователя

Чек-лист с прогрессом «N из 7» — в приложении: «Ещё» → «Перед запуском».
Кнопка **«Скопировать инструкцию»** рядом с чек-листом копирует этот план
в буфер — можно отправить помощнику или сохранить в заметки.

1. **Реквизиты**: «Ещё» → «Реквизиты и налог» — ИНН, ОГРНИП, адрес, банк,
   БИК, счёт (без них не сформировать документы).
2. **Поставщик**: «Ещё» → «Поставщики» → добавьте первого (город, режим
   отгрузки, контакты — только для вас).
3. **Позиция**: «Позиции и остатки» → «+» → мастер из 4 шагов (культура →
   атрибуты → цена/остаток → фото). На 4-м шаге можно прикрепить фото.
4. **Канал**: «Каналы» → «+» — свой Telegram-канал (тип, охват, теги).
5. **Бот**: добавьте [@aylatica_sales_bot](https://t.me/aylatica_sales_bot)
   **администратором** в свой канал (пошагово — раздел ниже). Проверка —
   «Ещё» → «Telegram-бот».
6. **Первая публикация**: «Разместить» — приложение подберёт каналы,
   сгенерирует текст (нужен `OPENROUTER_API_KEY` в Render env) и запостит
   в ваш канал через бота.
7. **Первая сделка и документ**: сделка из лида («Инбокс» или «Сделки») →
   «Счёт»/«Договор»/«ТН»/«УПД» — PDF скачивается из карточки сделки
   (пошагово — разделы ниже).

R2 (шаг 2–5 выше) — опционально: для фото позиций и рекламаций.

## Как добавить своего бота в канал

Бот [@aylatica_sales_bot](https://t.me/aylatica_sales_bot) — ваш «тихий
ассистент»: публикует объявления в ваши каналы и принимает вопросы
покупателей. Чтобы он работал с вашим каналом, сделайте его администратором
(30 секунд):

1. **Создайте канал** в Telegram (если ещё нет): New Channel → имя
   (например, «Семена Кубани»), тип — публичный или приватный.
2. **Добавьте бота**: управление каналом → «Администраторы» →
   «Добавить администратора» → введите `@aylatica_sales_bot`.
3. **Права бота**: достаточно «Публиковать сообщения» — включите этот
   тумблер, остальные права не нужны и не запрашивайте.
4. **Проверьте**: откройте приложение → «Ещё» → «Telegram-бот» —
   в блоке «Каналы для автопостинга» появится ваш канал со значком «бот».
   Напишите в бота `/start` — сообщение должно прийти в «Инбокс».

Что бот МОЖЕТ: публиковать ваши объявления в этом канале (кнопка
«Опубликовать через бота» в шаге «Текст» мастера «Разместить») и отвечать
на вопросы покупателей. Что НЕ может: писать в чужие чаты —
anti-ban-правило приложения, чужие площадки остаются полуавтоматом
(текст + deep link + отметка «размещено»). Если бот не появился в списке:
проверьте, что он админ (не просто подписчик), и нажмите «Обновить статус».

## Как создать первую сделку

Сделку можно создать из лида (сообщение покупателя боту) или вручную.
Пошагово:

1. **Откройте** «Сделки» → кнопка «+ Новая сделка» (внизу справа).
   Или «Инбокс» → карточка лида → «Сделка» — контакт подставится сам.
2. **Шаг «Товар»**: выберите позицию из каталога — цены подставятся,
   укажите объём (кг) и при желании скорректируйте цены. Если у лида
   есть ИНН — впишите, он попадёт в документы. Налоговый режим
   подставляется из профиля, меняется по месту.
3. Смотрите превью: **выручка, налог, маржа после налога** считаются
   сразу (маржа зелёная — сделка стоит свеч).
4. **Шаг «Доставка»**: самовывоз / ТК / попутчик. Для ТК — кнопка
   «Рассчитать доставку» (предварительная оценка, не тариф ТК).
5. **«Создать сделку»** — она появится как черновик. Дальше статусы
   по таймлайну: «К оплате» → «Оплачено» → «Отгрузить» → «Доставлено» →
   «Закрыть». Отгружаем **только после полной оплаты** — предоплату
   не берём, доставку оплачивает покупатель.

## Как сгенерировать документ

Счёт, договор, ТН и УПД — PDF из карточки сделки, продавец в них вы
(white-label, поставщик не упоминается).

1. **Реквизиты**: «Ещё» → «Реквизиты и налог» — ФИО/название, ИНН, адрес,
   банк, БИК, счёт (ОГРНИП — для ИП). Без них документы не сформируются —
   приложение честно скажет «Сначала заполните реквизиты».
2. Откройте **«Сделки» → карточка сделки** → блок «Документы».
3. Нажмите нужную кнопку — **Счёт / Договор / ТН / УПД**: PDF
   сгенерируется и сразу скачается. Документы можно пересоздать —
   все остаются в карточке с номерами.
4. «Счёт» удобен на статусе «Ожидает оплаты»: выставили — отправили
   покупателю, он оплатил — нажимаете «Оплачено».

## FAQ — частые вопросы

**AI не отвечает / текст не генерируется. Что делать?**
Проверьте `OPENROUTER_API_KEY` (или `GLM_API_KEY`) в Render →
agropost-api → Environment. Приложение при сбое AI не падает: текст
собирается шаблоном, а тост честно скажет «AI недоступен». Первый запрос
после «сна» бесплатного tier'а Render — ~30 сек, подождите и повторите.

**Как сменить пароль для входа?**
Пароль живёт в env `OWNER_PASSWORD_HASH`. Сгенерируйте новый хеш:
`cd apps/server && bun run hash-password`, вставьте его в Render →
agropost-api → Environment → `OWNER_PASSWORD_HASH` → сохраните
(сервис перезапустится). Логин задаёт `OWNER_LOGIN` там же.

**Как экспортировать данные?**
«Аналитика» → вкладки «Сводка» / «Каналы» / «Позиции» → кнопка
«Экспорт в CSV» — файл скачается с устройства. Значения с =,+,-,@
экранируются (защита от formula-injection в Excel).

**Приложение «спит» и открывается долго.**
Это бесплатный tier Render: web-статика не спит, api-сервис засыпает
через 15 минут бездействия, первый запрос его будит (~30 сек). Для работы —
норма, ждать не нужно перезагрузки страницы.

**Фото не загружаются на позицию.**
Без настроенного R2 фото до 8 МБ хранятся в базе (медленно, но работает),
видео — только с R2. Настройте R2 по инструкции выше — файлы уйдут в бакет.
Если в мастере «Каналы»/«Пульт» пусто — обновите страницу, каталог догрузится.

**Бот молчит, сообщения не приходят в инбокс.**
«Ещё» → «Telegram-бот»: если webhook не установлен — кнопка
«Установить webhook». Проверьте `TELEGRAM_BOT_TOKEN` в env и что бот админ
в канале. Напишите боту /start — сообщение должно появиться в инбоксе.

**Как обновить приложение до новой версии?**
В «Ещё» внизу — раздел «Версия и обновления»: текущая версия и дата.
Обновления — из репозитория GitHub (ссылки там же); деплой на Render —
кнопкой «Manual Deploy» (Pull latest) или автоматом при пуше в main.

## Непреложные правила

- **White-label**: покупатель не видит поставщика — ни в объявлениях,
  ни в ответах ИИ, ни в документах. Внутренние экраны — исключение.
- **Anti-ban**: автопостинг только в свои каналы через бота; чужие чаты
  и Авито — полуавтомат (текст + deep link + отметка «размещено»).
- **Парсер**: только обезличенные цены/названия/ссылки, без телефонов и ФИО.
- Предоплату не берём: отправка только после полной оплаты.
- Доставку оплачивает покупатель — в маржу не входит.
- Все секреты — в `.env`; в репозитории только `.env.example`.

## Безопасность (этап 5.1)

- **Авторизация владельца**: приватные маршруты API закрыты серверными
  сессиями (cookie HttpOnly + SameSite=Lax, в БД — только SHA-256 хеш
  токена). Пароль проверяется Argon2id-хешем из env; открытой
  регистрации нет; вход лимитируется (10 попыток / 15 мин).
- **CORS**: только доверенные origin (`TRUSTED_ORIGINS`), credentials —
  только для них; мутирующие запросы с посторонним Origin → 403.
- **Telegram webhook**: URL строится только из серверной конфигурации
  (RENDER_EXTERNAL_URL / TELEGRAM_WEBHOOK_URL); секрет
  X-Telegram-Bot-Api-Secret-Token проверяется в постоянном времени,
  пустой секрет в production — приём выключен (fail-closed).
- **Парсер**: `/api/parser/*` за авторизацией; Node → Python ходит с
  внутренним секретом `PARSER_SECRET` (сервер-сервер, без секрета в
  фронтенде/логах); публичный вызов Python `/run` невозможен.
- **Законность источников**: MTProto-сбор публичных Telegram-каналов
  ВЫКЛЮЧЕН по умолчанию (`TG_COLLECT_ENABLED=0`); Агросервер —
  только sitemap-путь с обязательным robots.txt (недоступен → отказ,
  fail-closed), сниппеты урезаны до 120 символов и вычищаются от
  телефонов/@usernames/email/URL.
- **PWA-приватность**: Service Worker кеширует только статическую
  оболочку; ответы `/api` в кеш SW не попадают; logout уничтожает
  серверную сессию и чистит клиентские сторы.
- **CSV-экспорт**: защита от formula injection (значения, начинающиеся
  с = + - @ табуляции/переводов строк, экспортируются как текст).
