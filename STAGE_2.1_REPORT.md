# Этап 2.1 — Починка превью + гео-ротация каналов (готово)

Дата: 2026-11-24 · Версия: 0.3.1 · Статус: **завершён, задеплоен**

## Что сделано

### Часть A. Превью — починено (реальный баг, не среда)

**Симптом**: кнопка «Publish» в превью ZAI падала с «Sorry, there was a
problem deploying the code»; `next build` в корне превью падал на
prerender «/»: `useLocation() may be used only in the context of a
<Router> component`.

**Причина**: два экземпляра модулей. Превью живёт в песочнице Next-приложения
(`/home/z/my-project`), а его страница импортирует react/react-router-dom
из корневого `node_modules` (React 19.2.3, react-router-dom 7.18.6);
экраны `@agropost/web/*` после `bun install` в `apps/web` резолвили те же
пакеты из `agropost/apps/web/node_modules` (React 19.3.1). Два Router-контекста
→ падение на prerender. Именно поэтому деплой превью падал ещё с этапа 2.

**Фикс**: из `agropost/apps/web/node_modules` удалены дубликаты
`react`, `react-dom`, `react-router`, `react-router-dom` — и страница,
и экраны резолвят единственные экземпляры из корня превью; Vite-сборка
`apps/web` не пострадала (ре-резолв в корневые пакеты).

**Проверка**: `next build` — ✓ Compiled successfully, 12/12 страниц,
все /api-маршруты. **превью: починено, деплоится.**
(Если после `bun install` в apps/web дубликаты вернутся — повторить
удаление этих четырёх пакетов из apps/web/node_modules.)

### Часть B. Гео-ротация каналов

- **Prisma**: `Channel.city` (String?, город ротации) и
  `Listing.publishedCount` (Int, default 0). Аддитивная миграция —
  существующие записи не затронуты (применена к Neon через `prisma db push`).
- **Seed — 14 каналов** (было 10): у Барахолки Динского района город
  «Динская»; новые для ротации в Ростовской области — «Ростов-Агро»
  (Ростов-на-Дону, SEEDS+GENERAL, охват 1500), «Барахолка Таганрога»
  (Таганрог, GENERAL+SEEDS, 900), «Шахты куплю-продам» (Шахты, GENERAL,
  700), «Новочеркасск аграрный» (Новочеркасск, SEEDS+LIVESTOCK, 1100).
  **Отклонение от промта (задокументировано)**: «Ростов-Агро» упомянут
  как канал этапа 2, но в сиде этапа 2 его не было — добавлен как четвёртый
  новый канал, иначе тест-сценарий «Таганрог/Шахты/Ростов в ротации»
  невоспроизводим. Итого 14, а не 13.
- **Демо-история ротации** (upsert по id, не трогает данные пользователя):
  Ростов-Агро и Новочеркасск «размещали» 2 дня назад → cooldown;
  Таганрог и Шахты — «никогда» → первый recommendedCity = Таганрог,
  после публикации в Таганроге — Шахты.
- **shared/rotation.ts** — единый источник правды (как pricing/attributes):
  `COOLDOWN_DAYS = 3` (хардкод), `daysSince`, `isCoolingDown`,
  `cooldownDaysLeft`, `lastPublishedMap`, `rotationGroup`, `recommendedCity`,
  `buildRotation`, `rankForRotation`, `withRotationInfo`, `channelHistory`.
- **API**:
  - `POST /api/positions/:id/suggest-channels` — сортировка: тег вида товара
    (фильтр, как в этапе 2) → свой регион → «не публиковали/давно
    публиковали» (cooldown-каналы вниз) → активность → охват. В ответе:
    `rotation` (регион, города с `daysSince`/`available`/`cooldownDaysLeft`,
    `recommendedCity` — только при ≥2 городах одного региона) и у каждого
    канала — `cooldown: boolean`, `daysSince: number | null`;
  - `POST /api/listings` — идемпотентен по паре (позиция, канал): повторный
    запуск потока возвращает существующий черновик, дублей не создаёт
    (раньше каждая итерация потока создавала новую строку);
  - `PATCH /api/listings/:id` — повторная отметка PUBLISHED обновляет
    `publishedAt` и наращивает `publishedCount` (без создания новой строки);
    счётчик `usedToday` аккаунта — только при первом переходе в PUBLISHED.
- **Экраны (apps/web)**:
  - виджет «Ротация по региону» в шаге «Каналы» мастера (появляется при ≥2
    городах): регион, города с подписями «никогда»/«2 дня»/«ждать N дн»,
    recommendedCity выделен акцентом + строка «Сегодня размещаем в: …»;
  - бейдж «⏳ N дн» на cooldown-каналах подборки (выбрать можно —
    с предупреждением);
  - в карточке канала и его view-sheet — «Город» и «Последнее размещение:
    N дней назад (здесь размещали N раз)» / «Никогда не размещали»;
  - в ленте Пульта: «размещено в N каналов · Города: Таганрог, Шахты»;
  - поле «Город» в форме канала (необязательно, пусто — весь регион).
- **Превью**: мок-API синхронизирован 1:1 (city, publishedCount,
  идемпотентный POST, повторный PUBLISHED, rotation в suggest-channels,
  та же демо-история через shared/seed-data), мета — 0.3.1 / stage 2.

## Архитектурные решения (вопрос → ответ)

| Вопрос | Решение |
|---|---|
| Где хранить cooldown-логику? | `shared/rotation.ts` — единый источник для Fastify, apps/web и превью (как pricing/attributes). Выбор пользователя. |
| Порог cooldown? | 3 дня хардкод (`COOLDOWN_DAYS`), без настройки в UI. Выбор пользователя. |
| Cooldown по каналу или по паре (позиция, канал)? | По каналу: банят канал за частоту постинга автора, а не за конкретный товар. |
| «Никогда не размещали» vs «7 дней назад»? | «Никогда» — лучший: сортируется выше (свежая аудитория). |
| Какие каналы попадают в ротацию/виджет? | Тег товара ИЛИ GENERAL (барахолка «куплю-продам» принимает любой товар — иначе «Шахты» не попадает в сценарий). В саму подборку каналов — только строгие совпадения тега (семантика этапа 2 сохранена). |
| Порядок критериев ранжирования? | Спецификация: тег → регион → daysSince DESC → активность → охват. Cooldown-каналы естественно уходят вниз (у них daysSince мал). Гео-приоритет Кубани сверху сохранён. |
| recommendedCity при равных «никогда»? | Больший охват городов-кандидатов (в демо: Таганрог 900 > Шахты 700). |

- Бейдж «⏳ N дн» — на каналах подборки (suggest-channels); в полном

  сидовые записи с фиксированными id; каждый повторный сид сбрасывает

  через API (как в этапе 2).
