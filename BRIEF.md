# BRIEF — АгроПост

Техническое задание на мобильное веб-приложение (PWA) для white-label
посредника по торговле посевными семенами трав и грецким орехом.
Этот файл — источник правды для всех этапов разработки.

---

## 1. Что это и для кого

Мобильное веб-приложение (PWA) для **одного пользователя** — посредника, который
торгует посевными семенами трав и грецким орехом. Пользователь работает
**white-label**: покупатель думает, что товар принадлежит ему, и **никогда не видит
поставщика** — ни в объявлениях, ни в ответах, ни в документах.

Приложение — **«тихий помощник»**, а не ERP. Главное действие — «Разместить товар».
Остальное (поставщики, парсинг, аналитика) — вторично и не должно создавать
ощущение давления.

## 2. Бизнес-модель

- Пользователь закупает у поставщиков, продаёт с **наценкой 15–20%** сверху.
  Наценку назначает сам.
- **Предоплату не берёт.** Отправка — только после **полной оплаты**.
- **Доставку оплачивает покупатель.** В маржу пользователя логистика не входит
  (но фиксируется в сделке).
- Юрформа: **ИП + самозанятый**. Налог учитывается в марже.
- Рекламации: пользователь отвечает перед покупателем, но фиксирует претензию
  и может переадресовать поставщику (модуль `claims`).

## 3. Товары и поставщики

**Товары**:

- Семена: люцерна, эспарцет, суданка, разнотравье. Мешки 25/50 кг.
- Грецкий орех: сетки/мешки 25 кг, закупка ~100 ₽.

**Поставщики** (у каждого — свой набор):

- Локации: Павловская (основная), Ленинградская, Тихорецк.
- У одного поставщика — 2 сорта люцерны и орех; у другого — 3 сорта люцерны,
  эспарцет, суданка.
- Условия отгрузки: **сам грузит в ТК** (при выезде за пределы Павловской —
  возможна небольшая доплата за дорогу) или **продаёт со склада** (погрузка за счёт
  поставщика). Своего склада у пользователя нет.
- Мин. партию задаёт **пользователь**, не поставщик.
- Медиа (фото/видео) присылает поставщик. Пользователь может наложить водяной знак.
- Сертификаты: у части продукции есть, у части нет. Галочка «есть сертификат»
  + вложение.

**Ключевое**: у каждой культуры — **свой набор атрибутов**. Нельзя делать жёсткие
поля «сорт + класс». Нужны **шаблоны культур**:

- Люцерна → сорт, репродукция, всхожесть %, засорённость %, год урожая.
- Эспарцет → сорт, репродукция, всхожесть %.
- Суданка → сорт, репродукция, всхожесть %.
- Орех → калибр, влажность %, выход ядра %, год урожая.

Позиция поставщика хранит эти атрибуты как **JSONB** по шаблону культуры.
В UI — аккуратная сетка «показатель: значение».

## 4. Как работает продажа

**Каналы** (по приоритету): Telegram (основной), Авито, Агросервер, Max, Юла.
Позже — другие.

- Каждый канал в каталоге имеет: тип, ссылку, регион, **теги**
  (`семена` / `орех` / `животноводство` / `опт`), охват, активность,
  привязанный аккаунт.
- При размещении позиции приложение **само предлагает 3–5 каналов**,
  отфильтрованных по тегам и гео-приоритету (ЮФО и новые территории — первыми
  для семян; для ореха — федеральные с пометкой).
- **Мультиаккаунты**: 3–4 на каждой площадке, отдельные сессии, лимиты, дневные
  квоты, журнал действий.

**Правила публикации (anti-ban)**:

- **Свои каналы** (где пользователь — админ): автоматическая публикация через
  Telegram-бота.
- **Чужие чаты**: только **полуавтомат** — приложение генерирует текст, открывает
  чат по deep link, пользователь вставляет вручную, приложение отмечает
  «размещено».
- **Авито**: API платный → полуавтомат (сгенерировал → скопировал → открыл
  ссылку → вставил → отметил).
- **Агросервер / Max / Юла**: аналогично — генерация + deep link + отметка.

**ИИ (OpenRouter, ключ только на бэкенде)**:

- `/api/ai/listing` — генерирует текст под площадку (Авито — сухо и фактурно;
  Telegram-чат — живо, с эмодзи, но без перебора; Агросервер — профессионально).
  Учитывает атрибуты позиции. **White-label**: имя поставщика не упоминается.
- `/api/ai/reply` — черновик ответа покупателю в стиле владельца (учится на
  прошлых сообщениях).
- `/api/ai/advice` — «Что мне сделать сейчас?»: смотрит активные лиды, каналы,
  сделки → выдаёт 1–2 конкретных действия. **Только по кнопке**, не проактивно.

## 5. Логистика

- Способы: **самовывоз**, **ТК** (ПЭК, СДЭК, локальные — приоритет в радиусе
  50 км от Павловской), **попутчики/автобусы**.
- Калькулятор считает **от локации поставщика**, а не от абстрактного склада:
  мешки, паллеты, объёмный вес, цена и срок.
- **Без «оценки рисков»** — только цифры. Решение о рисках — за пользователем.
- Доставку оплачивает покупатель — это фиксируется в сделке, но **не вычитается
  из маржи пользователя**.

## 6. Деньги, документы, рекламации

- **Сделка**: позиция → покупатель → кол-во → цена продажи → полная оплата →
  отгрузка → доставка.
- **Маржа** = `(цена продажи − цена поставщика) × кол-во − налог`.
  Доставка — отдельно, за счёт покупателя.
- **Документы**: счёт, договор, ТН, УПД, печать. Генерируются из данных сделки
  (PDF).
- **Рекламации (`claims`)**: фиксация претензии (фото, описание, статус),
  опциональная переадресация поставщику. Внутри приложения — видно поставщика;
  покупателю — нет.

## 7. Парсинг цен конкурентов и поставщиков

**Цель**: знать актуальные цены **конкурентов** (таких же посредников) и
**поставщиков** (не продают ли дешевле напрямую).

**Источники (поэтапно)**:

1. **Агросервер** — HTML-парсинг (selectolax/Cheerio), без авторизации. Безопасно.
2. **Telegram** — Telethon (MTProto), **отдельный аккаунт** (не основной),
   лимит 1–2 запроса/сек, паузы, ≤500 каналов. Сбор только из публичных каналов.
3. **Авито** — **отложить**, только полуавтомат (открыть страницу вручную).
   Риск блокировки IP/аккаунта не оправдан на старте.

**Правила**:

- Собираем **только обезличенные данные**: цены, названия, характеристики,
  ссылки. **Без телефонов и ФИО** (152-ФЗ).
- Каждый адаптер имеет лимиты и статус («активен», «ограничен», «выключен»).
  Если источник блокирует — адаптер отключается, приложение не падает.
- Данные — в карточке позиции, маленькой строкой «Рынок: 85–95 ₽/кг»,
  обновляется раз в день. Не на главном экране.
- Уведомление — только по правилу пользователя (например, «конкурент ниже на
  10%»), не потоком.

## 8. UX и визуал

**Стиль «Warm Utility»** — тёплый минимализм. Приложение делает мощные вещи,
но ощущается легко.

**Палитра** (светлая тема по умолчанию):

- `bg-canvas #FAF8F5`, `surface-card #FFFFFF`, `surface-subtle #F2EFE9`
- `text-primary #2C2A27`, `text-secondary #7A756D`
- `accent #3E7C5A` (приглушённый зелёный), `accent-soft #E6F0EA`
- `warm #D98E5F` (терракота для срочности), `border #EAE5DE`

**Форма**: карточки 20px, кнопки 999px (pill), поля 14px, модалки 24px.
Тени только мягкие: `0 8px 24px rgba(44,42,39,0.06)`. Никаких острых углов.

**Типографика**: Manrope (кириллица). Заголовки 24/600, текст 16/500,
подписи 13/500.

**Принципы**:

- Mobile-first: max-width 480px по центру на десктопе, bottom nav, safe-area.
- Главный экран — **кнопка «Разместить»** (pill, accent). Не дашборд.
- Нижняя навигация: `Пульт`, `Разместить`, `Сделки`, `Ещё`.
- Skeleton-загрузка вместо спиннеров. Spring-анимации 200ms, scale 0.97
  при нажатии.
- **Тихий помощник**: остатки обновляются вручную, без автоматических
  напоминаний «пополните склад».

## 9. Технический стек и инфраструктура

- **Фронтенд**: React 19 + Vite + TypeScript (strict) + Tailwind CSS v4 +
  `vite-plugin-pwa`. Router: `react-router-dom`. State: `zustand`.
  Icons: `lucide-react`. Шрифт: `@fontsource-variable/manrope`.
- **Бэкенд**: Node.js + Fastify + Prisma ORM + PostgreSQL (Neon).
- **Медиа**: S3-совместимое хранилище (Cloudflare R2, presigned uploads).
- **ИИ**: OpenRouter, ключ только на бэкенде.
- **Telegram-бот**: grammY (только для своих каналов, где пользователь — админ).
- **Парсер**: отдельный Python-сервис (FastAPI + Telethon + httpx + selectolax),
  запускается по cron, пишет в ту же БД.
- **Инфраструктура**: GitHub (новый репозиторий `agropost`) → Render
  (`agropost-web` Static Site + `agropost-api` Web Service, free tier) →
  Neon (новый проект, новая база) → Cloudflare R2 (отдельный бесплатный
  аккаунт, бакет `agropost-media`) → OpenRouter (ключ пользователя).

## 10. Ограничения (не нарушать)

- **Avito API платный** → только полуавтомат. Никаких иллюзий об автопостинге.
- **Render Free** — web service спит через 15 мин, БД на Neon (данные не
  удаляются). Не использовать Render Postgres (удаляет через 30 дней).
- **Anti-ban**: автопостинг только в свои каналы через бота; чужие чаты —
  полуавтомат.
- **Парсер**: только обезличенные данные (цены, характеристики, ссылки),
  без телефонов и ФИО.
- **White-label**: покупатель не видит поставщика ни в объявлениях,
  ни в ответах ИИ, ни в документах.
- **Только бесплатные сервисы и free tiers.**

## Правила работы над кодом

- Код и имена сущностей — английский. Интерфейс — русский.
- TypeScript strict. Никаких `any` без обоснования.
- Все секреты (`DATABASE_URL`, `OPENROUTER_KEY`, `R2_*`, `TELEGRAM_BOT_TOKEN`) —
  только в `.env`, не в коде. `.env.example` — в репозитории.
- Не добавлять фичи, которых нет в этом ТЗ. Если что-то противоречит — спросить,
  не угадывать.

## Модель данных (минимум)

Supplier (имя, телефон, локация, режим отгрузки, заметки) →
CultureTemplate (название, тип seed/nut, схема атрибутов JSONB) →
SupplierPosition (supplier_id, culture_id, attributes JSONB, объём, вес мешка,
цена поставщика, наценка %, цена продажи вычисляется, мин. партия, сертификат
bool + файлы, медиа[], статус) → Listing (position_id, channel_id, текст,
статус, url) → Deal (position_id, lead_id, кол-во, цена продажи, себестоимость,
доставка (кто платит), налог, чистая маржа, стадия) → Claim (deal_id, описание,
фото, статус, переадресовано поставщику bool) → Document (deal_id, тип, файл).

Вспомогательные: Channel (название, тип, url, регион, теги[], охват,
account_id, заметки), Account (площадка, телефон, статус сессии, лимиты),
Lead (источник, контакт, регион, интерес, статус, напоминания),
Shipment (deal_id, способ, перевозчик, трек, стоимость),
CompetitorPrice (источник, запрос, цена, ссылка, дата, продавец обезличенно),
PriceAlert (правило, статус).

**Маржа**: `(цена продажи − цена поставщика) × кол-во − налог`.
Доставку платит покупатель — в маржу пользователя не входит.
