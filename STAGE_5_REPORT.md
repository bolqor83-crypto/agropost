## ЧАСТЬ A — Аналитика (просто, по запросу)

### API (`apps/server/src/analytics/`)

Новый модуль с узким интерфейсом `AnalyticsDb` (как `DealsDb` в этапе 4):
Prisma-реализация в `db.ts`, чистые вычисления в `service.ts`, роуты в
`routes/analytics.ts`.

| Роут | Что возвращает |
| --- | --- |
| `GET /api/analytics/summary?period=week\|month\|all` | выручка и маржа по **закрытым** сделкам, сделки (всего/закрытые/активные), средний чек, топ-3 культуры по марже, топ-3 канала по лидам, конверсия лид→сделка, новые лиды за сегодня, `lowData` (закрытых < 3) |
| `GET /api/analytics/channels?sort=margin\|leads` | по каждому каналу: охват, размещений, выходов, лиды, сделки, конверсия, средняя маржа, последняя публикация (дней назад). Сортировка по марже или по лидам |
| `GET /api/analytics/positions?sort=margin\|stock` | по каждой позиции: остаток, сделки, выручка, маржа, средняя цена, дней в наличии, последняя публикация. Сортировка по марже или по остатку |
| `GET /api/analytics/readiness` | чек-лист «Перед запуском»: 7 пунктов, прогресс «N из 7» |

Методология (честные, фиксированные правила):

- выручка/маржа/средний чек — только по сделкам в статусе CLOSED за период;
- конверсия — лиды за период, у которых появилась сделка (`Deal.leadId`);
- аттрибуция лида каналу — по последней PUBLISHED-публикации позиции,
  о которой спросил покупатель (прямого FK «лид→канал» в схеме нет);
- период «неделя» = 7 дней, «месяц» = 31 день (как в списке сделок);
- ошибочный `period` → 400 `VALIDATION_ERROR` с человеческим сообщением.

### UI

- **Пульт**: 3 карточки-показателя (маржа за неделю · активные сделки ·
  лиды за сегодня), клик → экран «Аналитика». Загрузка тихая, без блокировки.
- **Экран «Аналитика»** (`/analytics`, вход из «Ещё» и с Пульта):
  селектор периода (неделя/месяц/всё время) + 3 вкладки — Сводка,
  Каналы, Позиции; кнопка «Экспорт в CSV» на каждой вкладке
  (файл собирается в браузере, с BOM — Excel открывает кириллицу);
  при закрытых сделках < 3 — мягкое «Данных пока мало, аналитика
  появится после первых сделок».
- В «Ещё» раздел «Аналитика» открыт (этап 5).

## ЧАСТЬ B — Проактивный советник

`/api/ai/advice` расширен только контекстом (AI-слой не тронут):
промпт дополнен секциями, fallback-правила знают новые сигналы.

### Новый контекст (`ai/context.ts`, `buildExtendedAdviceContext`)

- лиды инбокса NEW/IN_PROGRESS: интерес, дней, отвечен ли;
- зависшие лиды — старше 3 дней без исходящего сообщения;
- активные сделки (AWAITING_PAYMENT, PAID, SHIPPED);
- зависшие сделки — AWAITING_PAYMENT дольше 2 дней;
- позиции в наличии без публикаций > 14 дней;
- каналы, доступные к публикации сегодня (cooldown прошёл);
- каналы без публикаций > 14 дней;
- новые лиды за сегодня.

### Fallback-правила (порядок: деньги сначала)

1. зависшие лиды → «Ответить N лидам» (high, /inbox);
   иначе свежие без ответа → тот же совет мягче;
2. зависшие сделки → «Напомнить об оплате N сделкам» (high, /deals);
3. черновики > 3 дней → завершить и разместить;
4. позиции без публикаций > 14 дней → «Опубликовать позиции»;
5. активные размещения → проверить отметки «размещено»;
6. каналы: отдохнувшие > 14 дней → «Опубликовать в каналах»;
   после cooldown → «Освежить каналы» (сегодня можно);
7. всё пусто → «Сейчас всё под контролем» (0 действий).

Максимум 3 действия — не перегружаем. `/inbox` добавлен в допустимые
ссылки (схема, промпт, сервис). Zod-схема контекста расширена
опциональными полями — старые вызовы работают как раньше.

## Чек-лист «что пользователю сделать перед запуском»

1. **Заполнить реквизиты**: «Ещё» → «Реквизиты и налог» — ФИО, ИНН,
   ОГРНИП, адрес, банк, БИК, счёт, налоговый режим. Без них не
   сгенерируются счёт/договор/ТН/УПД. Сейчас: не заполнено.
2. **Добавить свой канал**: «Ещё» → «Каналы» → добавить свой Telegram-канал,
   затем добавить бота @aylatica_sales_bot администратором в этот канал
   («Ещё» → «Telegram-бот» → автопостинг). Сейчас: не добавлен.
3. **AI-ключ** (опционально, для AI-текстов): Render → agropost-api →
   Environment → `OPENROUTER_API_KEY` = ваш ключ → Save. Пытался внести
   ключ в env через Render API — токен `rnd_…` отдаёт 401 Unauthorized
   (недействителен/истёк), поэтому сделать это программно не удалось —
   добавьте вручную (1 минута). Без ключа приложение живёт полноценно:
   советник — на fallback-правилах, тексты — на шаблонах.
4. **R2 (опционально, для медиа)**: Render env `R2_ENDPOINT`,
   `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET`,
   `R2_PUBLIC_URL` — когда появятся фото позиций.
5. Позиции/поставщики/лиды уже есть в БД — пункт 1–2 закрывает чек-лист
   до «5 из 7» (AI и R2 — опциональные).

Прогресс чек-листа виден в «Ещё» — карточка «Перед запуском».
