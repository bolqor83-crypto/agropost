**Дата**: 2026-11-25 · **Версия**: 1.0.0 (stage 7 из 7) · **main**: отчёт поверх кода этапа 7

Цель этапа — подготовить пользователя к реальной работе: документация,
обучающие подсказки, финальный чек-лист запуска. **Новых фич нет** —

## C. Финальный чек-лист запуска

- **C1 — 7 пунктов работают**: `requisites, supplier, position, channel,
  bot (@aylatica_sales_bot), ai (OPENROUTER_API_KEY), r2 (опц.)`.
  Юнит-тест: ровно 7 пунктов, у каждого подсказка «куда идти», r2 —
  optional, прогресс N/7 (analytics/service.test.ts). Маршрут
  `/api/analytics/readiness` и навигация по пунктам проверены браузерным
  аудитом («4 из 7 готово» на мок-данных).
- **C2 — «Скопировать инструкцию»**: кнопка под чек-листом в «Ещё».
  Копирует пошаговый план запуска (готовое с ✔, неготовое — нумерованные
  шаги с подсказками) в буфер обмена — можно отправить помощнику или
  сохранить. Clipboard API + fallback на execCommand; тост при успехе/отказе.
- **C3 — «Версия и обновления»** в «Ещё»: АгроПост 1.0.0, дата
  обновления (25 ноября 2026 — `releasedAt` из `/api/meta`), ссылки на
  репозиторий GitHub, README и руководство пользователя. В футере «Ещё»
  версия вместо «этап 6 из 6». Мета-маршрут сервера: `version: 1.0.0`,
  `stage: 7`, `releasedAt: 2026-11-25`, `stages.docs: true`.

## Что делать пользователю

Прод живой с этапа 6 (API 0.8.0, вход через OWNER_LOGIN, AI через
OpenRouter, R2 не настроен — base64). После этого коммита:

1. Render → agropost-api и agropost-web → **Manual Deploy** (Pull latest
   commit) — поднимется версия 1.0.0 со всеми подсказками и README.
2. Опционально: настроить R2 по README (5 env-переменных) — для фото и
   видео позиций; без R2 всё работает (base64).
3. Дальше — работать: «Ещё» → «Перед запуском» (чек-лист), «Скопировать
   инструкцию» — план запуска в заметки, руководство — docs/USER_GUIDE.md.

Проект завершён: все 7 этапов готовы, MVP функционально полный и
задокументированный. Возможное будущее (по запросу): Avito MCP-интеграция,
платные tier'ы хостинга, новые культуры.
