# ЭТАП 9 — Автоматизация публикации: YML-фиды и Авито через API

Дата: 25 ноября 2026. Коммит: `b768b9f` (push в main). База: этап 8 (`6c43896`).

## Что решает этап

Пользователь вручную размещал объявления на Авито, Зерно Он-Лайн и Своё
Фермерство — это рутина. Теперь:

- **Зерно Он-Лайн (zol.ru) и Своё Фермерство (svoefermerstvo.ru)** читают
  объявления из YML-фида сами: один раз вставляете ссылку в кабинет
  площадки — дальше всё обновляется автоматически.
- **Авито** — через официальный API (OAuth2 + Автозагрузка): dry-run с
  превью XML → подтверждение → Авито забирает фид по ссылке и
  создаёт/обновляет/снимает объявления сам.

Без ключей Авито и без FEED_TOKEN приложение работает как раньше
(полуавто) — без падений, с честными предупреждениями.

## Часть A — YML-фиды (apps/server/src/feeds/)

| Файл | Назначение |
|---|---|
| `types.ts` | Контракты: FeedShopInfo, FeedOffer, FeedData, FeedConfig |
| `yml.ts` | Генератор YML по стандарту Яндекс.Маркета (escape, категории-культуры) |
| `avito-xml.ts` | Генератор Avito Ads formatVersion=3 + локальный валидатор |
| `data.ts` | Сборка FeedData из позиций IN_STOCK (white-label текст из listing-text) |
| `config.ts` | FEED_TOKEN, FEED_SHOP_URL, PUBLIC_API_URL, TTL кэша |
| `service.ts` | Снапшот с кэшем 1 ч — один для YML и Авито (превью = факт) |
| `routes.ts` | GET /api/feeds/yml?token=, /api/feeds/avito?token= (публичные), /api/feeds/info |
| `runtime.ts` | Prisma-загрузчики + фабрика для тестов |

Логика фида: только позиции **IN_STOCK**; цена — **salePrice** (с наценкой);
описание — из `shared/listing-text.ts` (white-label, поставщик не
упоминается); фото — только абсолютные http(s)-URL из Media (data-URL
заглушки демо не отдаются); атрибуты — из JSONB позиции по схеме шаблона
культуры → `<param>`; `<offer id="pos-…">` — стабильный id позиции
(площадка обновляет, а не дублирует).

**Токен**: FEED_TOKEN (32 символа, `openssl rand -hex 16`). Без токена или
неверный → **403** (структура фида не раскрывается; токен <16 символов не
считается секретом — тоже 403). Кэш 1 час серверный + `Cache-Control:
public, max-age=3600`. При старте без токена — честный warn в логе.

YML-структура (golden set — в тестах): `yml_catalog → shop → currencies
(RUB rate=1) → categories (по культурам) → offers → offer{url, price,
currencyId, categoryId, name «Люцерна «Вега 87» РС1, всхожесть 92%»,
description, picture*, param*}`.

## Часть B — Авито API (apps/server/src/publishers/avito/)

| Файл | Назначение |
|---|---|
| `config.ts` | env AVITO_* + приоритет над AppSetting «avito» из UI |
| `auth.ts` | OAuth2: POST /token, form-urlencoded client_credentials |
| `client.ts` | HTTP-клиент: кэш токена до expires_in, Bearer, validate/upload/currentUpload |
| `autoload.ts` | dry-run (локальная валидация + удалённая) и publish (upload по ссылке) |
| `routes.ts` | /api/avito/{status,settings,check,dry-run,publish} |
| `runtime.ts` | Доступ к AppSetting; подмена загрузчика для тестов |

Эндпоинты по официальной спецификации: **POST /token** (grant_type=
client_credentials&client_id&client_secret), **POST /autoload/v2/validate**
(удалённая валидация XML; 404/405/501 у площадки → «недоступен», остаётся
локальная проверка лимитов: Title ≤ 50, Description ≤ 7500, Address ≤ 256,
фото ≤ 40, уникальность Id, обязательные теги), **POST /autoload/v1/upload
{url}** — «Загрузка файла по ссылке»: Авито сам забирает XML-фид, **GET
/autoload/v4/uploads/current** — состояние обработки.

**Dry-run → подтверждение**: сервер собирает РОВНО тот же снапшот, что
отдаётся площадке (общий кэш сервиса фидов), локально валидирует,
пробует удалённый валидатор, возвращает `{xml, offers, valid, warnings,
remote}`; UI показывает превью; публикация — только по кнопке
«Подтвердить отправку» после превью. Прямого API создания одиночного
объявления у Авито нет публично — точечная публикация идёт через
Автозагрузку (фид целиком: Авито сам синхронизирует каталог и снимает
объявления, которых нет в фиде) — это и есть «один товар по кнопке».

**Ключи из UI**: «Ещё» → «Настройки» → «Авито API»: client_id /
client_secret (маскируется) / ID профиля / телефон, «Проверить
подключение» (реально получает OAuth-токен), статус активно/не настроено.
env (AVITO_CLIENT_ID/SECRET/USER_ID/CONTACT_PHONE) сильнее — тогда поля
только для просмотра. Хранение — AppSetting (Neon).

## Часть C — бейджи автоматизации

`Channel.automationLevel` (enum AUTO/SEMI/MANUAL, default SEMI, миграция
идемпотентна + индекс). Мастер «Разместить» шаг 2, каталог «Каналы» и
Sheet канала:

- 🟢 **Авто** — YML-площадки (Зерно Он-Лайн, Своё Фермерство), Авито API,
  свой бот-админ (этап 3.2);
- 🟡 **Полуавто** — чужие чаты, Агросервер (текст готовит приложение);
- 🔴 **Ручной** — НССиС (только точка входа).

Seed обновлён: 20 существующих каналов → SEMI; добавлены 5 площадок
`ch-zol` (Зерно Он-Лайн, zol.ru, AUTO), `ch-svoe-fermerstvo`
(svoefermerstvo.ru, AUTO), `ch-avito` (Авито, AUTO),
`ch-agroserver` (Агросервер, SEMI), `ch-ncsis` (НССиС — торговая
площадка Национального союза селекционеров и семеноводов, MANUAL).
В дизайн-систему добавлена пара токенов danger/danger-soft (закон
пары warm/warm-soft, светлая и тёмная темы).

## UI

- **«Разместить» шаг 2** — бейдж у каждого канала; шаг 3 для Авито —
  кнопка «Опубликовать на Авито» → «Проверяю XML…» → превью (счётчик
  объявлений, «XML валиден», предупреждения, сам XML в прокручиваемом
  блоке) → «Подтвердить отправку» → «Отправлено в Авито», листинг
  помечается PUBLISHED. Ключи не заданы → жёлтый warning «Авито API не
  настроен» + прежний ручной флоу (скопировать/вставить).
- **«Ещё» → «Настройки»** (новый экран): «Авито API» (статус, вход),
  «Фиды площадкам» (YML-ссылка + копирование, число офферов, инструкция
  про FEED_TOKEN), ссылка на реквизиты/тему. **/settings/avito** — поля и
  «Проверить подключение».

## Что делать пользователю

1. **YML-фид**: `openssl rand -hex 16` → FEED_TOKEN в env Render →
   Manual Deploy → «Ещё» → «Настройки» → скопировать YML-ссылку →
   вставить в кабинет Зерно Он-Лайн и Своё Фермерство (подробно — README
   «Как подключить YML-фид»).
2. **Авито**: «Для бизнеса» → «Интеграции» → API → client_id/secret →
   AVITO_* в env (или ввести в «Настройки → Авито API») → «Проверить
   подключение» → в мастере «Разместить» у канала Авито — «Опубликовать
   на Авито» (dry-run → превью → подтвердить).
3. Миграция и сид применяются деплоем (migrate deploy + seed): новые
   колонки и таблица AppSetting создаются идемпотентно; 5 площадок
   появятся в каталоге каналов.
