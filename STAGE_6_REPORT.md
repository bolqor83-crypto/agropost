## 1. ЧАСТЬ A — абстракция хранилища (base64 | r2)

`apps/server/src/storage/`:

- `types.ts` — `interface Storage { upload(key, contentType, bytes) → {url, key}; delete(url) }`, `parseDataUrl()`;
- `base64.ts` — MVP-реализация: data-URL прямо в строке БД, `delete` — no-op;
- `r2.ts` — Cloudflare R2 через `@aws-sdk/client-s3` (PutObject/DeleteObject), публичный URL в БД; клиент S3 инжектится для тестов;
- `factory.ts` — выбор по env: **R2_CONFIGURED=false → base64; true+5 значений → r2; true без ключей → безопасный фолбэк base64; не задан → авто (r2, когда все 5 значений `R2_ENDPOINT/BUCKET/ACCESS_KEY_ID/SECRET_ACCESS_KEY/PUBLIC_URL` на месте)**. Синглтон с кешем, `resetStorage()` для тестов.

Все пути сохранения файлов переведены на `storage.upload()`:

| Файл | base64-режим (сейчас) | R2-режим |
|---|---|---|
| PDF документов (`Document.fileUrl`) | data-URL в БД (как раньше) | объект в бакете + URL; `GET /api/documents/:id/file` отдаёт **302-редирект** на публичный URL |
| Фото рекламаций (`Claim.photos`) | data-URL в БД | объект `claims/<claimId>/…` + URL |
| Медиа позиций (`Media.url`) | data-URL в БД (новое — раньше просто не грузились) | объект `positions/<id>/…` + URL; сохранён и старый presigned PUT-путь |

Прочее: `GET /api/meta` теперь отдаёт `"storage":{"mode":"base64"|"r2"}`; при старте в base64-режиме — честный warning в лог; `.env.example` + `render.yaml` документируют `R2_CONFIGURED`.

## 2. ЧАСТЬ B — фото рекламаций

- API: `POST /api/claims/:id/photos` (data-URL, bodyLimit 16 МБ) и `DELETE /api/claims/:id/photos/:index`; валидация: JPEG/PNG/WebP, ≤10 МБ, ≤12 фото на рекламацию; объект в R2 удаляется best-effort.
- Сервис `addClaimPhoto/removeClaimPhoto` — через `deps.storage` (тестируемо).
- UI: ClaimSheet — «Прикрепить фото» (мультивыбор, превью, удаление до сохранения; загрузка после создания рекламации, по одному, устойчиво к ошибкам); в карточке сделки — галерея фото рекламации с удалением по одному.

## 3. ЧАСТЬ C — медиа позиций

- Новый сервис `apps/server/src/media/service.ts` (MediaDb-интерфейс, как DealsDb этапа 4) + `POST /api/positions/:id/media/upload` (data-URL, bodyLimit 36 МБ).
- Правила: **base64-режим — фото ≤8 МБ в БД; видео в base64-режиме честно отклоняется (415 VIDEO_NEEDS_R2 — тяжело для базы); R2-режим — фото/видео до 25 МБ в бакет.**
- UI (мастер, шаг 4): по `storage.mode` из meta — R2 → прежний presigned PUT прямо в бакет; base64 → JSON-загрузка через сервер. Честные предупреждения: «фото будут сохранены в базе (медленно), рекомендуем настроить R2», чип режима «R2»/«БД».
- SVG-заглушки из демо больше не нужны: загрузка реальная в обоих режимах.

## 4. ЧАСТЬ D — полировка: найдено и починено

Браузерный аудит (`scripts/stage6/browser-audit.mjs`, Playwright + собранный dist против мок-API, охрана как на проде): **40/40** — 12 экранов на 375px, тёмная тема, пустые состояния, выход/сессия, галерея фото рекламации, чек-лист.

Найденные и закрытые дефекты:

1. **Падение экрана профиля** на неожидаемом `dealTaxMode` («Cannot read properties of undefined (reading 'taxRate')», экран ошибки React Router). Двойной фикс: guard в ProfileScreen (`p.dealTaxMode ?? "IP_6"`) + тотальный switch в `dealTaxModeToProfile` (default вместо падения). Причина найдена воспроизведением на моке с кривым профилем.
2. **Холодный старт/диплинк на /positions** — мастер позиции показывал «Поставщиков пока нет» (каталог грузится на Пульте, PositionsScreen его не грузит; при обновлении страницы на /positions или заходе по прямой ссылке мастер оставался пустым). Фикс: мастер сам вызывает `load()` на mount (идемпотентно). Проверено: холодный переход на /positions → мастер показывает поставщиков.
3. Горизонтальные переполнения на 375px — не найдены ни на одном из 12 экранов (проверено по `scrollWidth <= clientWidth`).
4. Тёмная тема — переключатель в профиле (ToggleRow), класс `dark`, аналитика/ещё без переполнений; PWA: манифест (name/short_name/theme/background), иконки 192/512/maskable, apple-touch-icon, SW precache — всё на месте.
5. Пустые состояния: аккаунты/позиции/сделки/инбокс — осмысленные с кнопками (аудит).

## 9. Инструкция: включить R2 (4–5 переменных в Render → agropost-api)

1. Cloudflare → R2 → Create bucket `agropost-media` → Settings → Public Access → подключить `*.r2.dev` домен.
2. R2 → Manage API tokens → Create token (Object Storage Read & Write, ограничить бакетом) → скопировать Access Key ID + Secret.
3. Render → agropost-api → Environment: `R2_ENDPOINT` (S3 API аккаунта), `R2_BUCKET=agropost-media`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_PUBLIC_URL` (https://pub-xxxx.r2.dev) → Save.
4. Проверка: `GET /api/meta` → `"storage":{"mode":"r2"}`; лог при старте без предупреждения про base64.
