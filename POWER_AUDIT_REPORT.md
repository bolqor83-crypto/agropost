## 1. Главный баг: «приложение не заходит по заданному коду» — найден и исправлен

### Что происходило

Симптом: вводишь логин/пароль — кнопка «Войти» отрабатывает, но приложение **возвращается на экран входа**. Со стороны выглядит как «неверный код», хотя сервер отвечал **200 OK** и создавал сессию.

### Корневая причина (подтверждена в реальном браузере)

| Факт | Детали |
|---|---|
| Где жил фронт | `https://agropost-web.onrender.com` (Render Static Site) |
| Где жил API | `https://agropost-api.onrender.com` (Render Web Service) — **другой домен** |
| Как ходили запросы | Фронт вызывал API cross-origin с `credentials: 'include'`; сервер ставил cookie `agropost_session` для домена API |
| Что делал браузер | Cookie сессии — **сторонняя (third-party)** для домена сайта. Браузеры её отбрасывают: Safari/iOS (ITP — всегда), Chrome в режиме инкогнито и с включённой блокировкой сторонних cookie, Playwright-сборки Chromium |
| Итог | `POST /api/auth/login` → 200 + `Set-Cookie`, но cookie не сохраняется → следующий `GET /api/auth/session` → `authenticated:false` → фронт редиректит на `/login`. Вход выглядит бесконечным |

Воспроизведение в аудите: логин через реальный браузер — POST 200, `document.cookie`/cookie-store **пусто**, приложение на `/login?redirect=%2F`. При этом тот же пароль через curl (cookie вручную) работал — поэтому раньше баг «не ловился».

### Исправление (same-origin API, без переписывания архитектуры)

1. **Render Static Site `agropost-web`** — добавлено rewrite-правило:
   `source: /api/*` → `destination: https://agropost-api.onrender.com/api/*` (подстановку делает сама `*`; синтаксис `:splat` Render не подставляет — это проверено, при нём путь доходил искажённым).
2. **`VITE_API_URL` удалён** из env статик-сайта и из `render.yaml` — клиент (`apps/web/src/api/client.ts`) без него собирается с **относительным `/api`**: запросы идут на собственный домен сайта, Render их проксирует на API.
3. Cookie сессии стала **первой (same-origin)** — её принимают все браузеры.
4. CSRF-проверка Origin осталась рабочей: прокси передаёт `Origin` как есть; `TRUSTED_ORIGINS=https://agropost-web.onrender.com` уже доверен (проверено: Origin сайта → 200, посторонний Origin → 403).
5. `render.yaml` синхронизирован с прод-настройкой (оба rewrite-правила), README и док-комментарии клиента обновлены.

### Верификация (реальный браузер, 390px)

- Логин `agropost` + пароль → **переход на Пульт**, cookie сохранена, сессия живёт (14 дней, скользящий TTL);
- Обход **всех 16 экранов** по прямым URL — ни одного редиректа на /login, консоль **чистая**;
- Повторный вход после выхода — работает; вход после холодного старта API — работает (первый запрос ~30–50 с — особенность free-тарифа Render, не баг).

**Бонус-фикс:** View Transitions теперь включаются только на готовом документе (`readyState === "complete"`) — раньше первый переход после загрузки не укладывался в 4-секундный лимит Chrome и сыпал «Transition was aborted… DOM update timed out» в консоль (было 4–5 за обход, стало ≤1, перехватывается, на работу не влияет). Добавлен регрессионный тест.
